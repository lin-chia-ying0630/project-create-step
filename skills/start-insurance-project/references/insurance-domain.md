# 保險領域基礎詞彙與建模檢查

本文件提供開案起點，不取代商品條款、公司資料字典或適用地區法規。

## 契約關係人

| 中文名稱 | 英文參考 | 建模提醒 |
|---|---|---|
| 要保人 | policyholder / applicant | 與保險人訂立契約並通常負擔保費；不必然等於被保險人。 |
| 被保險人 | insured | 其生命、身體、財產或責任為保障標的。 |
| 受益人 | beneficiary | 依契約取得保險給付；需記錄順位、比例及有效期間時應另建關聯。 |
| 保險人 | insurer | 承擔保險責任的機構。 |

同一自然人可同時具多個角色，但角色本身不可合併。以 party/person 與帶生命週期的 role 關聯表達，避免在所有資料表重複整份個資。

## 契約與保障

| 概念 | 建模提醒 |
|---|---|
| 保單 | 使用穩定內部 ID；外顯保單號與批次序號的唯一性另以 constraint 表達。 |
| 商品／險種 | 版本與生效期間不可省略；不可假設現行版本適用所有歷史保單。 |
| 主約／附約 | 表達依附關係及各自保障、生效、終止與狀態。 |
| 保障項目 | 將保額、幣別、等待期、除外與期間連到正確契約版本。 |
| 保費 | 分開表示應繳、實繳、頻率、幣別、稅費及調整，不以單一浮點欄位概括。 |

## 生命週期與時間

- 將業務狀態與流程狀態分開，例如保單有效狀態不等於契約變更案件的處理狀態。
- 分開保存申請、送審、核准、承保、生效、停效、復效、終止及滿期事件。
- 歷史查詢需要 as-of date 時，採有效期間、版本或 event/audit 模型，不直接覆寫現值後遺失歷史。
- 時區、營業日、保險年齡與周年日算法必須由正式規則確認。

## 契約變更與理賠

- 契約變更以案件、變更項目、欄位差異、附件、核准結果及生效資訊建模。
- 送審前後快照需定義來源、格式、版本與可追溯性。
- 理賠申請、事故、文件、審查、決定與給付各有不同生命週期，不合併為一個狀態欄位。
- 所有正式決定保存操作者、時間、理由、規則版本與 correlation identifier。

## 安全與個資

- 以最小權限限制 party、健康、財務、文件與理賠資料。
- API response 只傳送畫面必要欄位；列表及 log 進行遮罩。
- 加密傳輸與靜態資料；金鑰、憑證及 token 置於秘密管理機制。
- 測試使用合成資料，避免把正式資料複製到本機、測試環境或版本控制。
- 資料保留、刪除、匿名化、存取紀錄及跨境要求依適用地區正式政策確認。
